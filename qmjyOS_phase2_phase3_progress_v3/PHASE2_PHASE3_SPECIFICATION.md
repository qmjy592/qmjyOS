# qmjyOS 第二、第三阶段实施规范

> 基线：qmjyOS `main` 分支公开文档与本轮上传的 29 文件本地源码快照。
>
> 说明：仓库正式文档已定义第一阶段“系统骨架”与第二阶段方向；当前仓库未找到正式的第三阶段规范。因此本文将第三阶段作为基于现有系统架构分层新增的实施规范，不把它描述成仓库已有的历史决定。

## 0. 当前基线与边界

### 第一阶段已完成的基础

- 模块目录边界、公共头文件、模块依赖和状态模型。
- QBoot handoff 协议和 QBuild v0.5.0 构建/测试入口。
- 当前受支持目标为 x86_64 + BIOS。
- 有物理内存分配器、4 KiB 分页管理器、IDT/GDT/TSS、异常/IRQ 入口、Ring 3 基础往返、双任务协作式调度器、VFS/RAMFS/QFS/IDE 等实验性实现。

### 已知限制

- `MM_HEAP`、`PROCESS`、`THREAD`、`SCHEDULER_PREEMPTIVE`、`SYSCALL`、`RUNTIME` 等模块当前状态为 planned。
- 当前调度器是双任务协作式调度，不是定时器抢占式调度。
- 当前 Ring 3 代码是基础隔离地址空间与测试系统调用往返，不是完整进程模型。
- 当前异常处理以诊断并停止内核为主，没有完整用户进程故障隔离/恢复。
- 已存在的 IPC 与服务管理代码及其宿主机测试，不等同于已接入内核调度、用户地址空间和系统调用权限检查的运行时服务系统。
- 仓库文档未声明 QEMU/真实硬件启动已经完成全覆盖验证。

## 1. 第二阶段：内核基础设施与运行时正确性

本阶段承接仓库 README 中明确列出的 Phase 2 方向。

### P2.1 内核初始化与子系统顺序

目标：形成唯一、可诊断、可失败回滚的初始化主流程。

交付：
- 启动信息结构校验：magic、协议主版本、结构长度、内存映射条目大小、物理区间溢出检查。
- 初始化阶段：EARLY → ARCH → MEMORY → CORE → DRIVER → FILESYSTEM → LATE。
- 每个初始化项记录名称、阶段、状态和错误码。
- 同一初始化项不得意外执行两次；失败时停止后续依赖阶段。
- 在 IDT/GDT/TSS 与 PIC/PIT 状态准备完成之前，不提前开放 IF。

验收：初始化阶段顺序测试、重复注册/重复执行测试、失败传播测试、启动串口阶段日志。

### P2.2 物理内存、虚拟内存与内核堆

目标：将当前早期 PMM 与页表管理器推进为内核可复用的内存服务。

交付：
- 明确可用、固件保留、内核、引导信息、模块和页表区间的所有权。
- 将页表页分配从固定静态池迁移为受 PMM 管理的页，并保留明确的低端引导映射约束。
- 定义内核虚拟地址布局、用户区间与内核区间的边界。
- 实现带对齐、溢出检查、释放、重复释放检测的 `kmalloc/kfree` 基础堆；随后再增加 slab。
- TLB 失效与 CR3 切换必须只在目标架构层实现，通用内存接口不得直接操作 x86 寄存器。

验收：PMM 主机测试、页表主机测试、堆分配/对齐/合并/释放/耗尽测试；目标环境另行验证 CR3/TLB。

### P2.3 GDT、TSS、IDT、异常与中断

目标：统一中断栈帧契约，使异常诊断与用户态返回可验证。

交付：
- 书面定义 CPU 自动压入字段、软件压入字段和 15 个通用寄存器的统一栈帧。
- 区分 CPU 自动压入错误码的异常向量，避免错误的栈偏移。
- 异常报告至少包含 vector、error、RIP、CS、RFLAGS；Page Fault 另报 CR2。
- GDT 切换期间保留有效的过渡代码选择子；新 IDT 装载成功后才恢复用户数据段描述符。
- TSS.RSP0 与每任务内核栈绑定，不再把单一测试栈误当作多进程栈管理。
- IRQ 入口保存完整上下文、满足 SysV AMD64 调用栈对齐并统一 EOI。
- 用户态异常应终止/隔离对应任务，不应直接走内核 panic；内核态异常仍进入 panic。

验收：汇编帧偏移静态检查、异常向量主机侧帧构造测试、QEMU 下 #GP/#PF/IRQ0/系统调用入口测试。

### P2.4 任务、线程与调度器

目标：保留现有协作式基线，再建立安全的抢占式路径。

交付：
- 统一 TCB/进程对象、任务状态、内核栈、寄存器上下文和运行统计。
- 调度队列与任务状态转换：NEW/READY/RUNNING/BLOCKED/EXITED/ZOMBIE。
- 明确 `task_yield`、阻塞、唤醒、退出和回收的状态规则。
- 先验证 IRQ 上下文保存/恢复，再加入 PIT tick 驱动抢占；不得直接在未保存中断帧时调用普通协作式 `switch_to`。
- 处理任务退出后的栈与对象回收，不能释放当前正在使用的栈。

验收：双任务协作回归、抢占轮转、阻塞/唤醒、任务退出与回收、长时间 tick 稳定性测试。

### P2.5 系统调用 ABI 与用户地址空间生命周期

目标：从单一 `int 0x80` 测试转为稳定、可校验的系统调用入口。

交付：
- 固定 ABI 主/次版本、系统调用号、参数寄存器、返回值与错误约定。
- 建立系统调用注册/分发表。
- 入口读取用户 RIP/RSP/RFLAGS，校验用户地址范围和调用号。
- 所有用户指针必须经 copy-in/copy-out 或安全访问器处理，不能直接把用户指针当作内核指针解引用。
- 明确系统调用从 Ring 3 进入 Ring 0、使用 TSS 栈、返回 Ring 3 的完整路径。

验收：合法调用、未知调用号、非法用户指针、权限错误、用户态故障隔离测试。

### P2.6 设备、块存储与文件系统基础设施

目标：把现有 IDE/QFS 路径纳入稳定的设备与存储接口。

交付：
- 驱动仅通过块设备公共接口向上层提供读写/flush。
- 对设备容量、LBA 范围、扇区大小、超时和错误状态进行统一校验。
- 分区扫描拒绝越界与重叠分区。
- QFS mount/read/write/flush/remove 路径具有明确错误语义与一致性测试。
- 正常启动不得自动格式化数据盘；测试盘与系统启动盘严格分离。
- 对掉电一致性单独设计 journal/intent log/recovery，不以简单重排写入冒充事务保证。

验收：块设备 host tests、MBR 边界测试、QFS host tests、双次独立 QEMU 启动持久化测试与镜像写入范围哈希检查。

### P2.7 自动化测试与目标运行证据

交付：
- 区分 HOST_TESTED、BUILD_VERIFIED、BOOT_TESTED、RUNTIME_VERIFIED。
- QEMU 日志和磁盘测试产物保存在 `build/` 下，失败时保留证据。
- 每次测试记录目标架构、启动模式、工具链版本、命令、退出码和完整日志。
- 跳过测试不得记为通过。

验收：完整构建、模块检查、已有 host tests、QBoot BIOS 与 QFS IDE QEMU 测试；环境不支持时明确标为 SKIP。

## 2. 第三阶段：用户程序运行时与系统服务层

此阶段是依据仓库既有架构层次新增的规划。其前置条件是第二阶段的内存、任务、系统调用与异常边界达到可用状态。

### P3.1 ELF64 用户程序加载器

- 解析并验证 ELF64 header/program headers。
- 检查架构、文件长度、段边界、整数溢出、PT_LOAD 权限冲突和用户地址范围。
- 按段权限建立独立用户页表；W^X 默认策略，拒绝 W+X 段。
- 建立用户栈、参数、环境变量与最小 auxiliary vector。
- 失败时回滚全部已分配物理页和页表，不泄漏资源。

验收：有效 ELF、损坏 ELF、越界段、重叠段、W+X、内存耗尽与回滚测试。

### P3.2 进程与线程生命周期

- PCB/TCB 分离：进程拥有地址空间、句柄表、权限和退出状态；线程拥有寄存器上下文、内核栈与调度状态。
- 实现创建、启动、退出、等待和资源回收。
- 初期不承诺 Linux `fork` 语义；先实现可验证的 `spawn/exit/wait`。
- 每个用户线程有独立用户栈和内核栈；TSS/RSP0 在切换时更新。

验收：多进程独立页表、线程创建、退出回收、父子等待和故障隔离测试。

### P3.3 IPC 与句柄权限

- 将当前固定数组消息队列扩展为受权限约束的内核 IPC 对象。
- endpoint/handle 绑定进程所有权；跨进程传递需经过 capability/权限检查。
- 定义消息长度上限、排队策略、发送失败与接收超时语义。
- 在调度器支持阻塞/唤醒后，实现阻塞 receive；在此之前只提供明确标记的非阻塞接口。
- 线程安全与中断上下文约束必须写入接口契约。

验收：队列满/空、非法句柄、权限拒绝、消息复制、超时、进程退出时 endpoint 回收测试。

### P3.4 用户运行时与初始化服务

- 建立最小用户运行时入口和系统调用包装层。
- `init` 作为第一个用户进程，负责启动系统核心服务。
- 服务管理器、注册表、日志、配置组件从宿主机测试形态逐步接入用户进程/IPC。
- 服务依赖使用拓扑排序；启动失败时停止依赖者并保留错误状态。
- capability/权限检查必须在系统服务接口和 IPC 入口处执行。

验收：init 启动服务序列、依赖缺失/循环、服务启动失败回滚、服务重启策略测试。

### P3.5 Shell 与基础系统工具

- 提供最小终端输入输出接口。
- 首批命令：`help`、`echo`、`pwd`、`ls`、`cat`、`mkdir`、`touch`、`rm`、`ps`、`kill`。
- 命令由用户进程执行，不直接访问内核私有结构。
- 后续增加管道、重定向、作业控制。
- 中文版默认简体中文；国际版默认英文，技术符号保持一致。

验收：命令参数解析、路径访问、退出码、错误输出和中英文版本启动测试。

### P3.6 持久化系统与启动体验整合

- 用户进程通过 VFS 访问 RAMFS/QFS，不直接访问 IDE 寄存器。
- 逐步增加 `/dev`、`/proc`、`/sys` 的最小子集。
- 与 QBoot handoff 协议、启动参数和语言版本策略对接。
- 只有在独立镜像、故障恢复和数据一致性测试通过后，才扩大默认启用范围。

验收：独立启动、init 启动、Shell 运行、文件读写持久化、错误恢复和语言版本验证。

## 3. 跨阶段依赖顺序

1. 启动协议和初始化顺序稳定。
2. PMM/VMM/内核堆稳定。
3. GDT/TSS/IDT/异常帧与 IRQ 返回稳定。
4. 任务上下文、阻塞/唤醒和调度稳定。
5. 系统调用 ABI 与用户地址访问器稳定。
6. ELF loader 与进程生命周期。
7. IPC/capability 与用户服务。
8. init、Shell、系统工具与持久化整合。

任何下游阶段不得通过绕过上游安全边界来提前标记完成。

## 4. 验收状态规则

- `planned`：只有规划或接口。
- `experimental`：有部分源码或局部测试，未达到模块完整验收。
- `implemented`：完整实现、构建接入和针对模块的测试均已具备。
- HOST_TESTED 不等于 RUNTIME_VERIFIED。
- QEMU 测试没有真实运行记录时，不得标记 BOOT_TESTED/RUNTIME_VERIFIED。

## 5. 当前实际工作边界

本文件是第二、第三阶段的实施规范，不是完成声明。实施时必须逐模块提交源码、构建映射、依赖配置、host tests、QEMU tests 和证据记录。第一阶段原有构建、QFS 数据盘隔离、Ring 3 基础路径和双任务协作调度不得回归。
