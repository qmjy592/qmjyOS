# qmjyOS Public Interface Contracts

## 1. 目的

本文档定义 qmjyOS 公共头文件的职责、依赖边界和兼容规则。

公共接口是子系统之间的契约，不等于对应功能已经实现。

## 2. 公共头文件

| Header | 职责 |
|---|---|
| types.h | 固定宽度整数、地址和基础类型 |
| error.h | 全局状态码 |
| compiler.h | 编译器属性和屏障 |
| limits.h | 全局资源限制 |
| config.h | 编译配置 |
| version.h | 系统版本 |
| arch.h | 处理器架构抽象 |
| boot.h | 启动信息与交接协议 |
| kernel.h | 内核初始化流程 |
| log.h | 日志输出 |
| panic.h | 内核致命错误 |
| memory.h | 物理内存与虚拟内存接口 |
| task.h | 进程、线程和调度接口 |
| ipc.h | 进程间通信 |
| device.h | 设备与驱动管理 |
| block.h | 块设备读写 |
| fs.h | 文件系统公共接口 |
| syscall.h | 系统调用 ABI |
| module.h | 内核模块注册 |
| test.h | 测试注册与运行 |

## 3. 类型规则

1. 公共接口优先使用 qm_u8_t、qm_u32_t 等统一类型。
2. 物理地址使用 qm_phys_addr_t。
3. 虚拟地址使用 qm_virt_addr_t 或明确的虚拟地址类型。
4. 长度使用 qm_size_t。
5. 状态返回值使用 qm_status_t。
6. 公共结构体不得依赖编译器默认位域布局。
7. 涉及外部协议的数据结构必须明确版本和结构长度。

## 4. 错误处理规则

公共函数优先返回 qm_status_t。

成功返回 QM_OK。

失败返回对应 QM_ERR_*。

指针输出参数必须在成功时写入有效结果；失败时不得让调用方误认为结果有效。

## 5. 内存与所有权

每个接口实现必须明确：

- 谁分配内存
- 谁释放内存
- 指针有效期
- 是否允许并发访问
- 是否允许阻塞
- 是否允许在中断上下文调用

没有明确说明时，不得假设调用是线程安全的。

## 6. 架构隔离

通用内核只能依赖公共架构接口。

架构私有寄存器、异常帧、页表硬件格式和汇编入口应保留在对应架构目录。

## 7. ABI 兼容

对外协议和系统调用必须具有版本管理。

不兼容变更必须提升主版本。

新增结构体字段必须考虑结构长度和旧版本兼容。

不得在不更新协议版本的情况下改变已有字段语义。

## 8. 模块依赖

模块依赖以 config/modules.dep 为准。

不得通过头文件相互包含形成隐式模块依赖。

模块之间应通过公共接口通信。

## 9. 实现状态与验证证据

模块实现状态和验证证据是两个独立维度，不能混为一谈。

### 9.1 QBuild 模块实现状态

QBuild v0.5.0 的模块状态文件为：

    config/modules.status

当前只允许以下状态：

| 状态 | 含义 |
|---|---|
| planned | 仅规划，尚无可用实现 |
| experimental | 已存在部分实现或实验性实现 |
| implemented | 已有可用的模块实现源码并纳入构建映射 |

不得将 interface、partial、tested 或 verified 写入
config/modules.status，除非未来明确升级 QBuild 状态格式。

### 9.2 验证证据

验证证据单独记录，不作为 QBuild 模块实现状态：

| 证据 | 含义 |
|---|---|
| NOT_VERIFIED | 尚无相关验证记录 |
| SOURCE_CHECKED | 已检查源码或接口 |
| BUILD_VERIFIED | 对应构建成功 |
| HOST_TESTED | 对应主机侧测试通过 |
| BOOT_TESTED | 对应启动测试通过 |
| RUNTIME_VERIFIED | 已验证目标环境运行行为 |

一个 experimental 模块可以有部分功能通过测试。
这不意味着整个模块已经实现或经过完整验证。

### 9.3 状态判断规则

1. 目录存在或头文件存在不能证明模块已经实现。
2. 接口已定义不能证明接口已有运行时实现。
3. 编译通过不能证明运行正确。
4. 主机侧测试通过不能替代目标架构运行测试。
5. 跳过的测试不能记为通过。
6. 硬件验证必须记录目标架构和启动方式。

模块状态模型的完整说明见：

    docs/architecture/MODULE_STATUS_MODEL.md

## 10. 测试要求

公共头文件至少应通过独立宿主机编译测试。

模块实现应具有对应单元测试或集成测试。

涉及硬件和启动过程的功能还应具有目标环境验证记录。
